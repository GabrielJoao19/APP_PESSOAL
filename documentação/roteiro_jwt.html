Roteiro de Implementação JWT

Guia definitivo para proteger o backend do LifeOS

1

Instalação de Dependências

No terminal, dentro da pasta backend, execute o comando abaixo para instalar as bibliotecas de segurança do NestJS:

npm install @nestjs/jwt @nestjs/passport passport passport-jwt bcrypt
npm install -D @types/passport-jwt @types/bcrypt
  • @nestjs/jwt: O motor que fabrica e decodifica a pulseira (JWT).
  • @nestjs/passport: O padrão ouro de autenticação para Node.js, adaptado para Nest.
  • passport-jwt: A "estratégia" que ensina o porteiro a ler o cabeçalho Bearer.
  • bcrypt: Embaralha as senhas do usuário no banco (Hash).
2

Criptografando Senhas (Bcrypt)

Antes de salvar um usuário no usuarios.service.ts, devemos criptografar a senha enviada:

import * as bcrypt from 'bcrypt';

// Dentro da função criarUsuario():
const saltRounds = 10;
const senhaHasheada = await bcrypt.hash(dados.senha, saltRounds);
dados.senha = senhaHasheada; // Substitui a senha pura pelo Hash

return this.prisma.usuario.create({ data: dados });

Entendendo o código linha por linha:

  • import * as bcrypt: Traz a biblioteca para dentro do arquivo.
  • saltRounds = 10: O "Salt" é um texto aleatório misturado na senha. O número 10 é o "custo" do algoritmo (quantas vezes ele roda). 10 é o padrão da indústria: seguro o suficiente para barrar hackers, mas rápido o suficiente para não travar o seu servidor.
  • await bcrypt.hash(...): A função pesada que faz a matemática. Ela pega a senha "123456" e transforma num monstro tipo $2b$10$wK3.... Usamos o await porque criptografia de verdade demora alguns milissegundos de propósito.
  • dados.senha = senhaHasheada: Sobrescreve a senha limpa no objeto para garantir que o que vai ser salvo no Prisma é a versão embaralhada.
3

Criação do Módulo de Autenticação

Gere os arquivos do módulo de Auth rodando no terminal:

npx nest generate module auth
npx nest generate controller auth
npx nest generate service auth

Como funciona o auth.service.ts:

async login(email: string, senhaLimpa: string) {
  // 1. Acha o usuário
  const user = await this.prisma.usuario.findUnique({ where: { email } });
  
  // 2. Se o usuário não existir, já bloqueia na porta
  if (!user) {
    throw new UnauthorizedException('Credenciais inválidas');
  }
  
  // 3. Compara a senha digitada com a criptografada do banco
  const senhaBateu = await bcrypt.compare(senhaLimpa, user.senha);
  if (!senhaBateu) {
    throw new UnauthorizedException('Credenciais inválidas');
  }
  
  // 4. Monta o Payload e assina (Gera a pulseira)
  const payload = { sub: user.id, email: user.email };
  return {
    access_token: this.jwtService.sign(payload),
  };
}

Entendendo a fabricação do Token:

  • O que é o Payload? É a "bagagem" de dados abertos que vai viajar dentro do JWT. Usamos a sigla sub (Subject / Sujeito) para guardar o ID do usuário por ser um padrão mundial. Também podemos guardar o email. Atenção: Nunca coloque a senha aqui, pois o Payload pode ser lido por qualquer pessoa na internet!
  • this.jwtService.sign(payload): Esta é a "fábrica" em si. O NestJS pega o seu Payload, pega uma Palavra Secreta (que só o seu servidor conhece) e carimba tudo isso gerando a "Pulseira VIP" (o token gigante cheio de letras aleatórias).
  • access_token: Retornamos o token em um formato JSON padronizado para o frontend receber, salvar e passar a usar em todas as requisições.
4

Protegendo as Rotas (Guard)

Criamos um arquivo jwt.strategy.ts para validar a assinatura do Token usando uma chave secreta no arquivo .env (ex: JWT_SECRET="minha-senha-super-secreta").

Depois, para fechar a porta de qualquer Controller (como o de finanças), basta colocar um cadeado no topo do arquivo:

import { UseGuards } from '@nestjs/common';
import { JwtAuthGuard } from '../auth/jwt-auth.guard.js';

@Controller('financas')
@UseGuards(JwtAuthGuard) // <-- ESSE É O CADEADO!
export class FinancasController {
  // Nenhuma rota aqui funciona mais sem o Bearer Token!
}
